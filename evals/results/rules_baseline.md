## 三点解读

### 1. challenge 上的准确率不是失败，三分之一是正确地拒绝作答

challenge 的 30 条里有 10 条移除了 `extruder_current`。失去这个信号后，部分堵塞与参数性欠挤出无法区分，而两者处置相反——猜测的期望值是负的。基线在这 10 条上全部输出 `UNKNOWN`，因此弃权率恰为 0.333，而**作答时准确率仍有 0.750**。

只报一个准确率数字会把这种正确行为记成失败。这就是为什么弃权率必须与准确率并列呈现。

### 2. 故障级准确率低估了实际表现

dev 上故障级准确率 0.960，但**处置类别准确率 1.000**。原因是被混淆的两类（`THERMAL_DRIFT` 与 `UNDEREXT_PARAM`）同属 `PARAM_FIXABLE`——分错了，但打印机要做的事完全一样。

真正到达设备的是动作，不是标签。所以两个指标都要报。

### 3. 安全指标在三个划分上均为 0

"堵塞被判成参数路径可接受的类别"这一项在 dev / holdout / challenge 上都是 0.000。这是本项目最关心的失效模式——它意味着向受阻的喷嘴增大流量。`tests/test_diagnosis_rules.py::TestSafety` 对每类堵塞跑 25 个种子来固化这一性质。

## 已知局限

- 数据全为合成，指标存在上界。基线在 dev/holdout 上表现强，**这在预期之内**：仿真器的故障 signature 虽有重叠，但仍比真实产线干净。
- 一个强基线是有意为之。若后续 LLM / RAG / Skills 配置无法超过它，那本身就是应当如实报告的结论，而不是把基线调弱来制造提升。
- `THERMAL_DRIFT` 召回偏低（holdout 0.667）是当前主要失效模式：温度偏差与流量轻微下降的组合在边界处仍会被归为参数问题。

## 修复记录

首次运行 dev 得 0.850，`THERMAL_DRIFT` 召回仅 0.250 —— 规则把流量分支排在温度分支之前，而热漂移本身会让流量轻微下降（0.94–0.985），于是热漂移案例先撞上流量分支、又因电流平坦被判为参数问题。

调整为：机械 signature（电流上升/塌陷）→ 温度越界 → 参数性欠挤出。物理依据是机械阻力可独立于温度判定；无机械 signature 而温度越界时，温度才是原因。dev 由此升至 0.960。

该调整在 dev 上完成，holdout 与 challenge 各只运行一次。
