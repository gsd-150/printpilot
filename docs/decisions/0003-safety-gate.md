# ADR 0003 — SafetyGate 不读取诊断结论

- **状态**：已接受
- **日期**：2026-07-30
- **里程碑**：M7

---

## 背景

holdout 上 `llm+skills` 把 **10% 的堵塞送进了参数路径**（3/30）。在真实设备上，
这意味着向受阻的喷嘴增大流量：挤出压力上升、驱动齿轮磨削料丝，一个可修的故障
变成一次拆机。

规划 v2 的 SG-1~SG-5 都是**一致性检查**：诊断为堵塞就不许下发参数补丁、
禁止提高被该故障禁止的参数、结果值不得越硬件边界、置信度不足则升级、
弃权不构成授权。

## 问题：一致性检查挡不住这 3 例

那 3 例**不是不一致的**。模型认为自己看到的是参数故障，于是提出了一个与该诊断
完全自洽的参数补丁。只检查"诊断与动作是否匹配"的门禁会**全部放行**——因为它们
确实匹配。

**错误在上游的诊断，而一个读取诊断的门禁会继承这个错误。**

这一点在实现前没有被识别出来。规划里"SafetyGate 会挡住误路由"的假设，
在遇到具体失效数据之后才被发现是不成立的。

## 决策：新增 SG-6，一条不读取诊断的证据联锁

SG-6 只读**感知层特征**。若原始信号显示机械阻力迹象，则禁止任何参数补丁，
无论上游得出什么结论。

三个触发条件：

| 条件 | 依据 |
|---|---|
| `current_delta > 0.015` | 推料力上升即存在机械阻力 |
| `flow_tail_mean < 0.30` | 挤出已基本停止，参数补偿无从生效 |
| `current_delta` 无法测量 | 无法排除机械阻力，不得在此前提下调参 |

**阈值刻意比诊断器判定堵塞的 0.023 更保守**，并有测试固化该关系。
联锁应当提前跳闸：误跳的代价是一次多余的暂停，漏跳的代价是一个喷嘴。

这就是真实机器上安全联锁的工作方式——**它们不询问控制器的意见，直接由传感器触发**。

## 实测

用 holdout 上模型**实际产出**的诊断重放（非构造样本）：

| | 堵塞进入参数路径 |
|---|---|
| 仅 SG-1~SG-5（一致性检查） | **3** |
| 加入 SG-6 | **0**（拦截 3，升级 2） |

`tests/test_safety_gate.py::TestRecordedFailuresAreBlocked` 把该结果固化为回归测试，
数据源为版本控制中的 `evals/runs/holdout-skills.json`。

## 后果

**正面**
- 误路由率由 0.100 降至 0.000，且不依赖诊断质量的改善
- 诊断层可以继续迭代而不影响安全下限
- 联锁的判据可被独立审计，不需要理解模型行为

**代价**
- 会误拦一部分真实的参数故障：凡是电流略有上升的案例都不再允许自动调参。
  这是有意的取舍，代价方向是"多停一次"而非"少停一次"。
- 联锁阈值是在 dev 分布上选的，真实设备上需要重新标定。
- SG-6 只覆盖挤出通路。其他故障类型若引入，需要各自的联锁判据；
  **不要假设本规则具有普遍性。**

## 一个仍然成立的局限

SG-6 保护的是**动作**，不是**诊断**。系统仍然会给出错误的根因，
只是不再据此改动参数。对操作者而言，"诊断为参数故障但被联锁拦下"是一个
需要人工介入的状态，而不是一个已解决的问题。

误路由率归零不等于系统判断正确——它等于**系统的错误判断不再触及设备**。
两者的区别必须在对外陈述时保留。
